# Asset Naming Conventions

How files are named in this project, for Godot 4.7.

> **Source of truth:** [`documentation/pipeline/pipeline.yaml`](pipeline/pipeline.yaml).
> This page is the readable summary. The YAML carries the actual regexes, and
> `.github/scripts/validate-pipeline-doc.py` checks them against the constants
> hard-coded in the CI scripts, so a convention cannot be changed in one place
> only. Change a rule there, not here.

## The shape

```
[prefix]_[asset_name]_[descriptor]_[variant]
```

- **prefix** — what kind of thing the file is (`sm_`, `sk_`, `t_`, `prefab_`, `level_`).
- **asset_name** — the object the file belongs to.
- **descriptor** — extra context, where it means something. For a texture, which map it is.
- **variant** — a number or word, only when there is more than one version.

Everything is **lowercase with underscores between words**. No spaces, no hyphens,
no camelCase, no PascalCase.

```
sm_office_building_small.gltf     ✅
t_rain_barrel_basecolor_02.png    ✅
SM_OfficeBuilding.gltf            ❌  uppercase
sm_rain-barrel.gltf               ❌  hyphen
rain barrel.gltf                  ❌  space
```

### Why lowercase

Godot generates lowercase names for everything it creates, so going with it is
cheaper than having every contributor change their editor settings. It also matches
Godot's own guidance in
[Project organization](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html),
which asks for `snake_case` folder and file names — partly to avoid case-sensitivity
breakage between Linux and Windows on export.

### Why prefixes, when Godot's docs don't use them

Godot's docs organise by folder and stop there. We add a type prefix on top because
the FileSystem dock is flat once you are inside an asset directory, and a prefix
sorts related files together and tells you what a file is before you open it. Node
names still follow Godot's convention — `PascalCase`, matching built-in node casing.

## The table

| Asset | Pattern | Example | Checked by |
| --- | --- | --- | --- |
| Static mesh | `sm_{object}.gltf`, `sm_{object}_{variation}.gltf` | `sm_rain_barrel.gltf` | review |
| Skeletal mesh | `sk_{object}.gltf` | `sk_wolf.gltf` | review |
| glTF buffer | `{mesh_stem}.bin` | `sm_rain_barrel.bin` | CI (blocking) |
| Texture map | `t_{asset_name}_{descriptor}.png`, `t_{asset_name}_{descriptor}_{variant}.png` | `t_rain_barrel_normal.png` | review |
| Model container scene | `{mesh_stem}.tscn` | `sm_rain_barrel.tscn` | review |
| Prefab scene | `prefab_{object}.tscn`, `prefab_{object}_{variation}.tscn` | `prefab_rain_barrel.tscn` | review |
| Level scene | `level_{level}.tscn`, `test_level_{level}.tscn` | `level_main.tscn` | review |
| Import sidecar | `{full_filename}.import` | `sm_rain_barrel.gltf.import` | CI (blocking) |
| Model spec | `{model_filename}.spec.yaml` | `sm_rain_barrel.gltf.spec.yaml` | CI (blocking) |
| Sprite source | `{lowercase_with_underscores}.aseprite` | `spider.aseprite` | CI (blocking) |
| Sprite sheet | `{lowercase_with_underscores}.png` | `spider_walk.png` | CI (blocking) |
| Audio | `{lowercase_with_underscores}.wav`, `.ogg` | `door_open.wav` | CI (blocking) |
| Script | `{lowercase_with_underscores}.gd` | `player_controller.gd` | review |
| Resource | `{lowercase_with_underscores}.tres` | `theme.tres` | review |

**"CI (blocking)"** means a workflow fails the PR. **"review"** means it is caught by a
human — the 3D naming patterns are documented and regex'd in `pipeline.yaml`, but nothing
enforces them automatically yet. Treat them as binding anyway.

Notes:

- The **model container scene** deliberately has no prefix of its own. It reuses its
  mesh's full stem so the pair reads as one unit: `sm_rain_barrel.gltf` and
  `sm_rain_barrel.tscn` sit side by side. This is Godot's inherited-scene wrapper around
  an imported model.
- The **glTF buffer** name is generated by Blender and referenced by name from inside
  the `.gltf`. Never rename it.
- The **import sidecar** keeps the asset's full filename including its original
  extension — `sm_rain_barrel.gltf.import`, not `sm_rain_barrel.import`.
- **Scripts** follow the
  [GDScript style guide](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_styleguide.html):
  `snake_case` file names, `PascalCase` for `class_name`. `gdlintrc` at the repo root
  sets the rules for names *inside* a script.
- **Resources** are Godot's `.tres` text format — version-control friendly, unlike the
  binary `.res`. See [Resources](https://docs.godotengine.org/en/stable/tutorials/scripting/resources.html).
  `theme.tres` is a [Theme](https://docs.godotengine.org/en/stable/tutorials/ui/gui_skinning.html) resource.
- **Sprite sheets** exported from Aseprite feed `SpriteFrames` / `AnimatedSprite2D` — see
  [2D sprite animation](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html).
  Animation tag names inside an `.aseprite` file follow the same lowercase-underscore
  rule and must be unique within the file.

## Texture descriptors

The descriptor says which map it is. Only these are accepted:

| Descriptor | Godot material slot |
| --- | --- |
| `basecolor`, `diffuse` | Albedo |
| `normal` | Normal Map — only the red and green channels are used |
| `orm`, `occlusionroughnessmetallic` | `ORMMaterial3D` — AO in R, roughness in G, metallic in B |
| `roughness` | Roughness |
| `metallic` | Metallic |
| `ao` | Ambient Occlusion |
| `emissive` | Emission |
| `height` | Height / parallax |
| `opacity` | Albedo alpha |

See [StandardMaterial3D and ORMMaterial3D](https://docs.godotengine.org/en/stable/tutorials/3d/standard_material_3d.html).

> **Never rename a texture by hand.** The `.gltf` references each image by URI, so a
> hand-rename breaks the model until someone edits the `.gltf` too — and the next export
> puts the old name back. If a filename is wrong, fix the exporter's filename pattern and
> re-export. That rewrites both at once.

Some committed assets still carry exporter-given mixed-case names such as
`RainBarrel_Base_Color.png`. They are grandfathered in. Fix them at the exporter on the
next re-export, not by renaming.

## Where files live

| Path | What goes there |
| --- | --- |
| `assets/3d/{category}/{object}/` | Everything for one 3D object: mesh, `.bin`, textures, every `.import` sidecar, the container scene, the spec |
| `prefabs/{category}/` | Prefab scenes, using the same category names as `assets/3d/` |
| `levels/` | Shipping level scenes |
| `test/levels/` | Scratch levels for trying assets out. Not shipped |
| `game/{game_object}/` | 2D art. Optionally nested one level deeper as `game/{game_object}/animations/` |
| `addons/` | Third-party plugins |

3D lives under `assets/3d/`, 2D lives under `game/`. The two roots are deliberately
different, not a mistake to reconcile — the aseprite validator hard-codes `game`. Some
older issue templates still ask for 3D assets under `game/`; that form is deprecated.

One directory per object, so a re-export touches nothing else.

## Files Godot generates

Importing an asset creates an `<asset>.import` sidecar next to the source file.
**Commit it.** Without it the asset's resource UID differs on every machine, so scene
references break for everyone but you. The corresponding processed files land in
`res://.godot/imported/` — that folder is *not* committed and is rebuilt automatically.

See [Import process](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/import_process.html).

`.github/workflows/check-import-files.yml` enforces this. On same-repo PRs it generates
and pushes the missing sidecars for you; on fork PRs it fails and uploads them as an
artifact instead.

## Formats

| Use | Never | Why |
| --- | --- | --- |
| `.gltf` | `.fbx` | FBX is proprietary with inconsistent importer behaviour across DCCs |
| `.wav`, `.ogg` | `.mp3` | MP3's encoder padding makes seamless loops impossible |
| `.png` | — | Textures are capped at 1024 px in either dimension for the web build |
| `.tres` | `.res` in source | Text resources diff; binary ones don't |

`.fbx` and `.mp3` are blocked by `flag-fbx-files.yml` and `flag-mp3-files.yml`. The
`.tres` row is Godot convention rather than a project rule — `pipeline.yaml` says nothing
about it and nothing checks it.

WAV files must be 44100 Hz, 16-bit, mono, normalised to −16 LUFS with a peak no higher
than −1.0 dBFS. `.github/scripts/validate-audio-files.py` checks all of it.

Format details:
[importing 3D scenes](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/index.html) ·
